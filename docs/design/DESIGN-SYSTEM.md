# DESIGN-SYSTEM — 视觉语言

这份文档管「长什么样、为什么这样」。它不给色值（在 [TOKENS.md](TOKENS.md)）、不给
组件 API（在 [UI-KIT.md](UI-KIT.md)）、也不列与画板的差异（在
[DEVIATIONS.md](DEVIATIONS.md)）。

适用对象：`apps/client` 的界面代码，以及需要在 `designs/graft-git` 之外新画界面的场合。
画板本身仍是结构与层级的来源；本文解释画板里那些重复出现的选择。

## 1. 六条原则

1. **原生优先**：输入、菜单、告警、滚动、窗口装饰、焦点与 VoiceOver 语义走系统；
   外观由自绘层按系统刻度实现。自绘的目的是补齐 NSH 没有的系统控件，不是发明新视觉。
2. **密而可读**：Git 客户端的密度是需求，不是缺陷。行高按系统刻度（28 / 24），
   不为了「呼吸感」放大到 Web 应用尺寸；可读性靠层级与留白实现，不靠加高行。
3. **层级靠表面与字重**：一个视图最多叠三层表面（内容 → 面板 → 面板内分层），字重
   三档。不用到处描边的方框、不用大写微标签、不用阴影制造层级（阴影只属于浮层）。
4. **一个主色**：系统蓝只做一档。危险色是独立语义，不是「红色的强调」。
5. **状态是设计的一部分**：loading / empty / error / disabled / 操作进行中 与正常态
   同等对待，先设计状态再设计主路径。
6. **深色与浅色等价**：没有只写浅色的键。新加颜色必须两个模式都有值，且对比度都过。

## 2. 表面：八层骨架，外加浮层与控件底

窗口骨架由一组明度接近、只差 4–8 个十六进制级的底色叠成。相邻表面的差异刻意小：
用户应当读到「这里是另一块区域」，而不是「这里有一张卡片」。

| 层 | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `content` | 主内容区、diff、表格正文 | `#FFFFFF` | `#1B1B1D` |
| `panel` | 检查器、历史区等次一级面板 | `#F7F7F9` | `#1F1F21` |
| `panel2` | 面板内的再分层（表头、分组底） | `#F1F1F4` | `#262628` |
| `sidebar` | 侧栏 | `#F4F4F6` | `#232325` |
| `bar` | 工具栏 | `#F5F5F7` | `#2A2A2C` |
| `titlebar` | 标题栏（含仓库页签条） | `#F0F0F2` | `#262628` |
| `tabbar` | 页签条底 | `#E9E9EC` | `#202022` |
| `status` | 状态栏 | `#F7F7F8` | `#242426` |
| `menu-bg` | 菜单与浮层底 | `#FCFCFD` | `#2C2C2E` |
| `field` / `btn` | 输入框与按钮底 | `#FFFFFF` | `#232326` / `#2C2C2F` |

浅色里越靠窗口边框（标题栏、页签条）越暗，深色相反。`status` 是刻意的例外：它在两个
模式都贴近 `panel` 的明度（浅色 `#F7F7F8`、深色 `#242426`），因为状态栏要与内容区分、
又不该像标题栏那样压住视线。深色的 `titlebar` 与 `panel2` 同值（`#262628`），标题栏靠
分隔线与页签条区分，不再多占一档。

层级只靠三点表达：底色差、1px `line` 分隔线、内边距。**不要**给面板加圆角卡片外壳，
也不要在面板里再套卡片；需要分区就画分隔线或换表面。

## 3. 文字

四档正文角色，外加两级标题；方向只有一个：越次要越小、越浅。

| 角色 | 尺寸 / 行高 | 颜色 | 用途 |
|---|---|---|---|
| 正文 `ui::BODY` | 13 / 18 | `text` | 行标题、标签、提交说明、按钮文案 |
| 次要 `ui::SECONDARY` | 11 / 15 | `text2` | 说明、帮助、表单提示、设置行副标题 |
| 元数据 `ui::META` | 11 / 15 | `text3` | 表头、计数、时间、作者、状态栏 |
| 代码 `ui::CODE` | 12 / 18 | `text` | diff、SHA、路径、tree |
| 面板标题 `ui::TITLE` | 15 | `text` | 面板与侧栏标题 |
| 页面标题 `ui::TITLE_LARGE` | 26 | `text` | 欢迎页英雄区 |

- **界面里不存在小于 11pt 的用户可见文字。** 画板的 8.5–10.5pt 是实现侧的已知偏离
  （见 [DEVIATIONS.md](DEVIATIONS.md)），不要为了「更像设计稿」把字号写小。
- 字重只有三档在跑：`NORMAL`（正文）、`MEDIUM`（按钮、标签、表头、选中页签/分段）、
  `SEMIBOLD`（弹窗标题、面板标题）。不用 `BOLD`。
- 选中页签与选中分段同时改字重与底色/下划线——只用其中一项，选中态在灰度截图里就丢了。
- 等宽字体只通过 `ui::code(..)` 或 `ui::MONO` 出现，不写 `font_family("SF Mono")`。

## 4. 间距与形状

- 基准 4；间距只用 4 / 6 / 8 / 12 / 16 五档（`ui::GAP_XS` … `GAP_XL`）。
  行内元素之间 4–6，控件之间 8，区块之间 12–16，页面留白 16–24。
- 行高：标准 28、紧凑 24（菜单项、快捷键行、键值行）；双行列表 44。
- 控件高：小 22、常规 28、大 32；工具栏项 26。
- 圆角：控件 6、面板 8、弹窗与卡片 10、应用图标 15；窗口圆角由系统绘制。
- 分隔线一律 1pt：`line` 常规、`line-soft` 面板内、`line-strong` 浮层与输入框描边。
- 不用胶囊、不用「左边一条彩色描边」的强调块。需要强调就用底色或字重。

## 5. 状态

| 状态 | 表现 | 约束 |
|---|---|---|
| hover | 底色换 `hover`（浅色黑 4.5%、深色白 5.5%） | 选中行不改 hover 色 |
| pressed | 实心按钮透明度 0.8；描边与 Ghost 按钮换 `line-soft` 底色 | 只出现在按压瞬间 |
| selected | `sel` 底色 + `text` 文字；页签与分段再加字重 | 焦点不在该列表时也不消失 |
| focus | 2pt `focus` 色轮廓，用 `outline` 不改布局 | 键盘可达处必须可见 |
| disabled | 透明度 0.45 | 必须能说出为什么禁用；不可点击但没有解释 = 缺陷 |
| invalid | 描边换 `danger` + 一行 11pt 错误文案 | 颜色之外必须有文案 |

状态不能只靠颜色表达：错误有文案、禁用有原因、diff 有 `+`/`−` 前缀、同步结果有文字。
这一条是给色觉障碍与灰度截图准备的。

## 6. 语义色

| 组 | 键 | 规则 |
|---|---|---|
| diff | `add-bg` / `add-word` / `add-ln`，`del-bg` / `del-word` / `del-ln` | 行底最浅、词强调最深，两者不同一档；别拿行底代替词强调 |
| hunk | `hunk-bg` / `hunk-fg` | 只用于 hunk 头，不用于整段折叠区 |
| 分支 / 标签 / 远端 | `branch-*` / `tag-*` / `remote-fg` | 分支与标签靠底色区分，不靠图标形状 |
| 图线 | `g1`–`g4` | 四条泳道循环使用；不新增第五色 |
| 语义 | `warn` / `danger` / `ok` | 只表达语义，不做装饰；`danger` 与 `destructive` 同值 |
| 头像 | `avatar-bg` / `avatar-fg` | 头像只用这一对底色与字色，不引入第三种 |

绿与红在同一屏（diff 的增删）是允许的，因为同时有 `+`/`−` 与列位置；其它场合不要用
红绿对立表达「通过/失败」，用图标 + 文案 + `ok`/`danger` 单侧着色。

## 7. 深色模式

- 同键不同值，不加新键。深色不是浅色反相：`content` 变最暗，`bar` / `panel` 反而更亮。
- 交互遮罩用半透明：`hover` / `press` 浅色是黑 alpha、深色是白 alpha；diff 底色深色
  用 alpha（`rgba(46,160,90,.17)`）而不是实色，避免叠在别的表面上失真。
- 深色下主按钮仍是 `#0A66E8`（`primary-bg` 不跟随 `primary` 变亮），因为要保证白字对比度。
- 新增键必须两个模式都有值；只写浅色会被 `theme_tests` 拦下（缺键）。

## 8. 动效

- 当前没有显式动画：浮层、弹窗、进度都是直接切换。这是可接受的状态，不是待补的缺陷；
  不要为了「更顺滑」给整屏加淡入。
- 需要加时：交互反馈 120–180ms、`ease`，不弹跳；hover 过渡不超过 200ms。
- 进度分两种：已知百分比用条 + 数值，未知用不确定态；不确定态不显示假百分比。
- diff 渲染、钩子日志这类「内容在更新」的地方不加过渡，避免掩盖状态变化。
- 系统的「减少动态效果」开启时，动画不能是唯一的状态提示。

## 9. 图标

- 来源是设计稿的 SVG sprite（`design/icons.rs`），没有 SF Symbols 接口可用。
- 四档：11 侧栏与状态图标（`Compact`）、12 按钮内（`Button`）、13 行内（`Inline`）、
  16 工具栏与页头（`Toolbar`）。
- 例外尺寸只有三处（9 行内折叠箭头、15 设置页分支、20 错误横幅），属于插画式用法，
  不要模仿着再加第四处。
- 图标按钮必须有无障碍名称；`ui::icon_button` 的 `label` 同时是可见提示与
  `accessibility_label`。

## 10. 文案与可访问性

- 英文默认、简体中文完整；文案按 +30% 预留宽度，超出截断并给提示，不挤压相邻控件。
- 正文对比度 ≥ 4.5:1，大字 ≥ 3:1，两个模式都要过；`text3` 是最浅的可读层级，不要再浅。
- 所有控件键盘可达、焦点可见、tab 顺序与视觉顺序一致；表格、树、页签的 role 由
  `nsh_base` 提供，页面不自造。

## 11. 不做什么

- 不做渐变背景装饰、不做模糊玻璃底（材质留待评估）、不做发光描边。
- 不做「卡片套卡片」，不做每个区块都加边框。
- 不用 emoji 当图标；不用全大写微标签（画板里 `side-head` 的 `text-transform` 已关掉）。
- 不在同一屏出现第二个主色按钮；主操作用 `Primary`，其余 `Secondary` / `Ghost`。
- 不为了对齐画板而写小于 11pt 的字、把工具栏压到 44、把行高收到 25——这些都在偏离清单里
  有记录，属于**已决定不做**，不是待办。
