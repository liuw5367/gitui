# 页面开发规范

适用范围：`apps/client/src/features/`、`app/`、`shell/` 下的页面与视图文件。目标是
一个页面的状态、动作与渲染各自有归属，评审时能按同一套标准判断是否完成。

## 1. 目录与职责

| 位置 | 放什么 | 不放什么 |
|---|---|---|
| `features/<name>/state.rs` | 本功能的 Signal、表单选项结构、页面内枚举 | `git` / `store` 调用、元素构建 |
| `features/<name>/commands.rs` | 用例、异步任务、错误映射、持久化调用 | 元素构建 |
| `features/<name>/view.rs` | 组合 `crate::ui` 与布局原语 | 文件 IO、Git 调用、跨功能写状态 |
| `features/<name>/ops.rs` | 对 `Tab` 的写操作，返回 `Result` | 页面状态、渲染 |
| `app/` | 引导、窗口、菜单、快捷键、跨功能写操作 | 单个页面的版式 |

- 跨功能动作走 `SessionHandle` 或 `app::ops`；页面不直接改其它功能的 Signal。
- 依赖方向只有 `git → domain` 和四个库 crate → `apps/client`；页面代码不引入反向依赖。
- 单文件超过约 500 行时按区域拆成 `view/` 子模块。拆出来的模块只服务本功能，不为
  形式分层制造只转发参数的包装。

## 2. 响应式契约

NSH 的 `dynamic` 只重建闭包内读取过信号的区域；`get_untracked()` 返回快照，不建立
订阅。页面挂载后不会因为任意状态变化整体重建，因此可变状态必须在读取处建立订阅。

| 场景 | 写法 | 避免 |
|---|---|---|
| 文本、计数、时间 | `text(move || ...get())` | 构建时 `get_untracked()` 后固定 |
| 条件结构 | `dynamic(move || ...)` | 用普通 `if signal.get()` 包 `child` |
| 列表过滤 | `each` 的每行在闭包里读取查询词 | 在 `each` 构建时算出 `visible` 后固定 |
| 控件属性 | 用 `dynamic` 包住控件，在闭包里传当前快照值；组件生命周期稳定时才传闭包 | 把闭包绑定交给会被销毁的 `dynamic` 子树 |
| 相对时间、派生摘要 | 每次渲染重算，或用刷新信号 | 挂载时算一次 `now` |

- 视图里禁止用 `get_untracked()` 读取会变化的 UI 状态。只在初值确实不会变化时使用，
  并在调用处注释原因。
- `dynamic` 会重建子树。输入框不要放进会被每次按键重建的区域，避免输入法与光标状态
  丢失。
- 列表的 `each` key 用稳定值（路径、id），不要用下标。
- `dynamic` 子树销毁时，`nsh_base` 组件的 `Prop` 绑定会随 owner 一起失效；把闭包绑定
  传给动态子树里的控件，会在销毁或切换时读到已释放的 owner。需要更新的控件用
  `dynamic` 包住并传快照值；表单里的复选改用 `ui::check::check_row_button`。
- `ui` 组件的可变属性优先保持静态签名。只有控件与页面同生命周期时，才把签名放宽为
  `IntoProp` 或闭包；不要为了少写一层 `dynamic` 把绑定送进会被销毁的子树。

## 3. UI 规则

- 只组合 `crate::ui` 的组件与 `view()` / `text()` / `scroll()` 等布局原语；已迁移
  页面不直接引用 `nsh_base`。
- 字号取 `ui` 刻度，颜色取 `design`，不写字号字面量、十六进制颜色与字体族；完整
  清单见 [UI-KIT](../design/UI-KIT.md)。
- 字号、控件高、行高以 macOS 原生刻度为准；画板与刻度的差异登记到
  [DEVIATIONS](../design/DEVIATIONS.md)。
- 需要新外观时先在 `ui/gallery.rs` 加示例，再在 `ui` 加变体；不在页面覆盖组件的
  颜色、字号或尺寸。
- 图标按钮必须给 `accessibility_label`；键帽提示必须对应真实可用的快捷键，不能只在
  画面上写一个组合键。
- 页面的布局常量（侧栏宽、最大内容宽、内距）放在文件顶部并注明画板来源；同一数值
  不要在多个函数里重复写。
- 设计中的控件先按画板呈现。后端能力尚未实现时，点击给出真实状态说明（说明弹窗、
  设置页导航或状态提示），不显示 `demo`、`模拟`、`待接入`、`敬请期待` 等字样，也
  不展示假账号、假仓库大小或假可见性。未实现项登记在计划与根 README 的已知限制，
  页面本身不承担说明职责。

## 4. 文案与错误

- 所有用户可见文案走 `i18n`；`en.json` 与 `zh-Hans.json` 的键集合保持一致，新增
  键两边同时加。
- 错误按表单归属：切换表单、重试或成功后清除，显示在触发动作附近。
- 不直接把 `GitError::detail()` 显示给用户：该函数只返回中文，英文界面会出现中文
  错误。按错误枚举映射 i18n；命令输出作为详情单独呈现。
- 每个异步动作至少三态：空闲、进行中、失败。进行中禁用重复提交，保留取消路径；
  失败可以重试。
- 空态给出下一步；有查询但无结果时显示无结果文案，不保留空分组标题。
- 操作文案说明后果，不复述标题。

## 5. 能力边界

- 设计需要、低层 crate 没有的能力：先在 `git` / `store` / `domain` 实现并增加测试；
  本轮不做的按第 3 节的未实现方式呈现，登记到计划与根 README。
- 业务逻辑不放进 `view`；不在 `apps/client` 复制 Git 行为。
- 改存储格式保持向后兼容：新增字段用可选列，旧文件可读，新文件对旧读取路径不产生
  误解。
- 跨 crate 改动同步对应 crate 的 README 与测试；公开签名只改一次，避免页面与低层
  同时扩散。

## 6. 文档与改动范围

- 有意的视觉或结构差异记录到 [DEVIATIONS](../design/DEVIATIONS.md)：写清画板值、
  实现值、原因、能否回退。未登记的差异按缺陷处理。
- 单页版式与按钮表以 [docs/pages](../pages/README.md) 为准；不要为了迁就实现修改
  页面文档，除非设计源同时变更。
- 用户可见的能力缺失写进根 README 的已知限制；一次性步骤、验收记录与批准摘要留在
  `plans.local/` 的计划里。
- 一次改动只服务当前页面与当前目标；不夹带无关重构、格式化或改名。
- 未获明确授权不提交、不推送。提交信息使用 Conventional Commits，类型用英文，标题
  与正文用中文。
