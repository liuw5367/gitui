# 页面验收

## 1. 自动检查

每次页面改动至少在仓库根执行：

```sh
cargo test
(cd apps/client && nsh check)
tools/check-ui.sh
python3 tools/design/tokens.py
```

`cargo test` 需要 PATH 中有 `git`；`crates/git` 与客户端测试会创建真实临时仓库。
只改客户端时可以运行 `cargo test -p nsh-app`，提交前仍执行一次全量。

- 纯函数（分组、过滤、路径缩写、默认值、错误映射）在定义文件内加 `#[cfg(test)]`
  测试。
- 命令用临时目录与真实 `git` 验证；测试结束清理临时目录，不依赖网络。
- 新增或修改 `ui` 外观时，`ui/gallery.rs` 要有对应示例；`tools/check-ui.sh` 与
  `guard_tests` 都要通过。
- 新增 i18n 键时确认两种语言的键集合一致。

## 2. 截图验收

- 产物写入 `files.local/shots/<名字>.png`。`files.local/` 已在 `.gitignore` 中排除，
  截图不提交。
- 用 `tools/shots.sh <名字>` 启动 debug 构建并截取应用窗口；脚本会重定向 HOME 与
  `APP_HOME`，不污染日常数据。
- 截图只作为行为证据，不作为像素基线；判断依据是 [docs/pages](../pages/README.md)
  与 [DEVIATIONS](../design/DEVIATIONS.md)。
- 欢迎页截图前脚本会清空自己的应用数据，保证从空列表开始。有最近仓库、三种表单与
  克隆失败的状态由欢迎页改造中新增的 debug 开关提供；在开关可用前，这些状态在运行
  中的应用里切换后手工截取，不要用 `welcome` 名字的脚本。
- 至少覆盖：

| 页面 | 状态 |
|---|---|
| 欢迎页 | 空列表 + Open、有最近仓库 + Clone、有最近仓库 + Init、克隆中、克隆失败、搜索无结果 |
| 欢迎页 | 英文与简体中文、浅色与深色 |
| 其它页面 | 本次改动直接影响的状态 |

- 分段与弹窗状态需要在运行中的应用里切换后截取；自动化开关随对应页面改造加入，
  加入前不得把未截到的状态当作已验证。

## 3. 完成定义

页面完成（UI）：

- [ ] 版式与 `docs/pages` 一致，差异已登记 DEVIATIONS
- [ ] 按钮表的每个控件有真实行为或真实状态说明，页面没有 demo/模拟数据字样
- [ ] 状态轴覆盖：列表空/非空、每个分段、进行中、失败、搜索无结果
- [ ] 响应式四件事成立：输入即过滤、勾选即变、分段即高亮、忙碌即禁用
- [ ] 双语、浅色/深色、键盘焦点与无障碍标签检查过
- [ ] 主要流程可仅用键盘完成；焦点顺序清楚、焦点可见，弹层关闭后焦点回到触发控件
- [ ] 改动触及的交互控件已用 VoiceOver 检查名称、状态与操作；不可用或未覆盖的路径明确记录
- [ ] 选择、错误、忙碌等状态有文字、图标或结构提示，不只依赖颜色或动效
- [ ] 关键状态截图存放在 `files.local/shots/`；截图只证明记录时的呈现，不代替键盘或 VoiceOver 验收

功能完成（按计划范围）：

- [ ] 计划列出的能力已实现，错误已本地化，三态与取消/重试可用
- [ ] 对应低层 crate 的测试通过
- [ ] 涉及长列表、异步操作或动态子树时，验证筛选/刷新后的对象身份、过期结果与上下文切换；不涉及的项目标记为不适用

交付前：

- [ ] 四项自动检查全绿
- [ ] 自动化结果与人工/平台检查分开记录；未执行的人工检查标为未验证，不写成通过
- [ ] DEVIATIONS、根 README 已知限制、相关 crate README 已更新
- [ ] 计划记录结果、验证与未完成项
